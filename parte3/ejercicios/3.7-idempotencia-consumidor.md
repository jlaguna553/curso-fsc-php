# Ejercicio 3.7 — Idempotencia del consumidor (6 pts)

## Objetivo

Probar que el loan-service ignora los eventos duplicados (at-least-once).

## Instrucciones

1. Verifica que `eventos_procesados` tenga PRIMARY KEY sobre `event_id`.
2. Publica el MISMO evento dos veces a la cola `loan_events`:

   ```bash
   # Obten el JSON exacto de un evento ya publicado
   docker compose exec rabbitmq rabbitmqadmin get queue=wallet_events \
     count=1 --format=raw_json > /tmp/evento.json

   # Re-publica 2 veces con la misma routing key
   docker compose exec rabbitmq rabbitmqadmin publish \
     exchange=prestaflow routing_key=wallet.event.transaccion \
     payload="$(cat /tmp/evento.json)"
   ```

   > Nota: para este ejercicio, edita el `event_id` del JSON y confirma
   > que SOLO la primera copia con el mismo ID se procesa.

## Resultado esperado (logs del worker)

```text
[12:00:01Z] INFO  Evento evt-TX-01 → APROBADO (puntaje 85)
[12:00:02Z] INFO  Evento duplicado ignorado: evt-TX-01      ← ✅ idempotente
[12:00:03Z] INFO  Evento evt-TX-02 → EN_REVISION (puntaje 55)  ← otro ID, sí procesa
```

## Verificación

```bash
docker compose exec postgres psql -U prestaflow -d prestaflow_loan -c \
  "SELECT count(*) FROM eventos_procesados WHERE event_id='evt-TX-01';"
# → 1 (una sola fila, aunque llegó dos veces)
```
