## Objetivo

Sacar la configuración del Deployment: valores no sensibles a un `ConfigMap`,
credenciales a un `Secret` (creado por kubectl, no versionado), y activar el
autoescalado con un `HorizontalPodAutoscaler`.

## Instrucciones

1. `configmap.yaml`: mueve al ConfigMap los valores que NO son secretos:
   - `APP_ENV: prod`
   - `DATABASE_URL` con el dnsname del postgres (ej: `postgresql://prestaflow:...@postgres:5432/prestaflow`)
   - `RABBITMQ_URL` apuntando al servicio `rabbitmq` del clúster
   - `MONEDA_DEFAULT: MXN`

2. Actualiza el Deployment: `envFrom: [configMapRef: { name: wallet-config }]`.

3. Crea el Secret via kubectl (NO lo versiones con el password en claro):
   ```bash
   kubectl create secret generic wallet-secrets \
     --from-literal=APP_SECRET=$(php -r 'echo bin2hex(random_bytes(16));') \
     --from-literal=POSTGRES_PASSWORD='prestaflow_segura' \
     -n prestaflow
   ```
   Y añade `secretKeyRef` en el Deployment para `APP_SECRET`.

4. `hpa.yaml`: `HorizontalPodAutoscaler` `wallet-service`:
   - min 2, max 10 réplicas
   - target CPU 70% (sin `resources` en el Deployment, el HPA NO funciona)

## Verificación

```bash
kubectl get cm wallet-config -n prestaflow -o jsonpath='{.data.APP_ENV}'
# → prod

kubectl get secret wallet-secrets -n prestaflow -o jsonpath='{.data.APP_SECRET}' | base64 -d | wc -c
# → 32 (16 bytes hex)

kubectl get hpa -n prestaflow
# → NAME: wallet-service, REFERENCE: Deployment/wallet-service, TARGETS: <unknown>/70%

kubectl autoscale 2>/dev/null; kubectl describe hpa wallet-service -n prestaflow | grep -E "Min replicas|Max replicas"
# → Min replicas:  2 / Max replicas: 10
```

**`k8s/configmap.yaml`**

```yaml
# k8s/configmap.yaml — Config NO sensible del servicio
#
# CONFIGMAP: separa la configuración del código (Doce-Factor Apps).
# Aquí va TODO lo que no es secreto: URLs, flags, defaults.
#
# Verlo aplicado:
#   kubectl get cm wallet-config -n prestaflow -o yaml
#
# Aplicar:
#   kubectl apply -f k8s/configmap.yaml -n prestaflow
apiVersion: v1
kind: ConfigMap
metadata:
  name: wallet-config
  namespace: prestaflow
data:
  # Entorno de ejecución
  APP_ENV: prod
  # BD: "postgres" es el DNS del servicio postgres DENTRO del clúster
  DATABASE_URL: postgresql://prestaflow:prestaflow_segura@postgres:5432/prestaflow
  # Broker: "rabbitmq" es el DNS del servicio de mensajería
  RABBITMQ_URL: amqp://prestaflow:prestaflow_segura@rabbitmq:5672
  # Default de negocio del dominio
  MONEDA_DEFAULT: MXN
```

**`k8s/hpa.yaml`**

```yaml
# k8s/hpa.yaml — Autoescalado horizontal
#
# HPA (HorizontalPodAutoscaler): observa las métricas de los pods y
# ajusta el número de réplicas entre min y max.
#
#   CPU > 70% promedio → escala HACIA ARRIBA (hasta 10)
#   CPU < 70% sostenido → escala HACIA ABAJO (mínimo 2)
#
# REQUISITO: el Deployment DEBE tener resources (lo tiene en
# deployment.yaml) — sin metrics-server o sin requests el HPA no escala.
#
# Probar el escalado (terminal 2):
#   kubectl run load --image=busybox --rm -it -n prestaflow \
#     -- sh -c "while true; do wget -q -O- http://wallet-service/api/salud; done"
#
# Aplicar:
#   kubectl apply -f k8s/hpa.yaml -n prestaflow
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: wallet-service
  namespace: prestaflow
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: wallet-service
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```
