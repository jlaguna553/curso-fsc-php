## Objetivo

Garantizar que el wallet-service no duplique depósitos ante reintentos del cliente.

## Instrucciones

1. Crea la tabla de idempotencia (SQL manual, fuera del ORM):
   ```sql
   CREATE TABLE IF NOT EXISTS idempotencia (
       clave         VARCHAR(100) PRIMARY KEY,
       procesado_en  TIMESTAMP NOT NULL DEFAULT NOW()
   );
   ```
2. Implementa `DoctrineIdempotenciaRepository` (puerto `IdempotenciaRepository`)
   con `INSERT ... ON CONFLICT DO NOTHING` (lección 3.2).
3. Inyecta el puerto en `RealizarDepositoCommandHandler`:
   - `existe($clave)` → devolver balance actual sin procesar
   - `registrar($clave)` → después del flush exitoso
4. **Comprueba la carrera:** dispara el mismo curl dos veces seguidas:

## Verificación

```bash
for i in 1 2; do
  curl -s -X POST localhost:8080/api/v1/billeteras/{ID}/deposito \
    -H 'Content-Type: application/json' \
    -d '{"monto":"500.00","moneda":"MXN","idempotency_key":"misma-clave"}'
done
# Las DOS respuestas deben decir balance_nuevo IDENTICO
# (ej: "500.00" y "500.00", NO "500.00" y "1000.00")

# Y solo hay 1 movimiento en la billetera:
curl -s localhost:8080/api/v1/billeteras/{ID} | jq '.total_movimientos'  # → 1
```
