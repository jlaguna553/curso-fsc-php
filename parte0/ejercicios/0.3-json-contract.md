# Ejercicio 0.3: Validar un Contrato JSON

## Objetivo

Aprender a validar contratos JSON entre servicios usando herramientas de
línea de comandos, una habilidad crítica para debugging en microservicios.

## Contexto

Cuando dos microservicios se comunican por JSON, un campo malformado puede
causar errores silenciosos. En fintech, esto puede significar dinero perdido.
Un validador de contratos por CLI atrapa estos errores antes de que lleguen
al código.

> **Herramienta**: usa `jq` y un script bash. Si aún no conoces `jq`, revisa
> la sección *"Inspeccionar y Validar JSON con jq"* de la lección 0.3. Y si
> nunca has escrito un script bash, la sección *"Validación Automática:
> Escribir un Script bash"* te enseña cada pieza que necesitas (crear el
> archivo, `set -euo pipefail`, argumento/stdin, exit codes).

## Instrucciones

### Paso 1: Preparar los datos de prueba

Crea `transaccion-request.json` con el contrato de depósito de la lección
0.3 (`monto`, `moneda`, `tipo`, `billetera_id`, `idempotency_key`). Crea
además variantes inválidas — por ejemplo `invalido.json` con `monto`
numérico — para probar tu validador. (Pista: un JSON de una línea se crea
con `echo '{...}' > archivo.json` o con un here-doc.)

### Paso 2: Escribir el validador

Escribe un script `validar-contrato.sh` (bash, con `#!/usr/bin/env bash` y
`set -euo pipefail`) que reciba la ruta de un JSON como argumento — o lea el
JSON desde stdin si no se pasa argumento —, use `jq` para validar el
contrato y cumpla TODO lo siguiente:

- **(a)** Si el archivo no existe, o no es JSON bien formado (`jq empty`),
  imprime `CONTRATO INVÁLIDO: ...` y termina con exit code 1.
- **(b)** `monto` DEBE ser de tipo string (`jq '.monto | type'`) y tener
  formato numérico positivo (dígitos con punto decimal opcional).
- **(c)** `moneda` DEBE tener exactamente 3 caracteres.
- **(d)** `tipo` DEBE ser uno de: `deposito`, `retiro`, `transferencia`.
- **(e)** `idempotency_key` NO puede estar vacío.
- **(f)** Si todo cumple: imprime `CONTRATO VÁLIDO` y termina con exit code 0.
  Si algo falla: imprime `CONTRATO INVÁLIDO:` seguido de cada error en una
  línea `  - <detalle>`, y termina con exit code 1.

### Paso 3: Probar ambos casos

Ejecuta el script contra tu JSON válido y contra las variantes inválidas
(monto numérico, moneda de 2 caracteres, tipo no permitido). Confirma que
solo el JSON válido produce `CONTRATO VÁLIDO`.

## Entregable

Archivos:
- `validar-contrato.sh` (ejecutable: `chmod +x`)
- `transaccion-request.json` (datos de prueba)
- (opcional) tus variantes inválidas

## Puntos

| Criterio | Puntos |
|---|---|
| Script valida tipo string de monto | 1 |
| Script valida longitud de moneda | 1 |
| Script valida valor de tipo | 1 |
| Script valida idempotency_key no vacío | 1 |
| Script maneja JSON malformado | 1 |
| Script funciona con stdin | 1 |
| **Total** | **6** |

```bash
#!/usr/bin/env bash
# validar-contrato.sh — Valida el contrato JSON de una transacción
# Uso: bash validar-contrato.sh archivo.json   (o JSON por stdin)

set -euo pipefail

# Fuente del JSON: argumento o stdin
if [[ $# -eq 1 ]]; then
    FILE="$1"
    if [[ ! -f "$FILE" ]]; then
        echo "CONTRATO INVÁLIDO: Archivo no encontrado: $FILE"
        exit 1
    fi
else
    FILE=/dev/stdin
fi

# Verificar que es JSON bien formado
if ! jq empty "$FILE" 2>/dev/null; then
    echo "CONTRATO INVÁLIDO: JSON malformado"
    exit 1
fi

ERRORS=()

# Validar que monto sea string
MONTO_TYPE=$(jq -r '.monto | type' "$FILE")
if [[ "$MONTO_TYPE" != "string" ]]; then
    ERRORS+=("monto debe ser string, no $MONTO_TYPE")
fi

# Validar que monto tenga formato numérico positivo
MONTO_VAL=$(jq -r '.monto' "$FILE")
if ! echo "$MONTO_VAL" | grep -qE '^[0-9]+(\.[0-9]+)?$'; then
    ERRORS+=("monto '$MONTO_VAL' no tiene formato numérico válido")
fi

# Validar que moneda tenga 3 caracteres
MONEDA_LEN=$(jq -r '.moneda | length' "$FILE")
if [[ "$MONEDA_LEN" -ne 3 ]]; then
    ERRORS+=("moneda debe tener exactamente 3 caracteres (tiene $MONEDA_LEN)")
fi

# Validar tipo sea uno de los permitidos
TIPO=$(jq -r '.tipo' "$FILE")
case "$TIPO" in
    deposito|retiro|transferencia) ;; # OK
    *) ERRORS+=("tipo '$TIPO' no es válido (usar: deposito, retiro, transferencia)") ;;
esac

# Validar que idempotency_key no esté vacío
KEY_LEN=$(jq -r '.idempotency_key | length' "$FILE")
if [[ "$KEY_LEN" -eq 0 ]]; then
    ERRORS+=("idempotency_key no puede estar vacío")
fi

# Resultado
if [[ ${#ERRORS[@]} -eq 0 ]]; then
    echo "CONTRATO VÁLIDO"
    exit 0
else
    echo "CONTRATO INVÁLIDO:"
    for err in "${ERRORS[@]}"; do
        echo "  - $err"
    done
    exit 1
fi
```

**Datos de prueba de referencia:**

```bash
cat > transaccion-request.json << 'EOF'
{
  "monto": "1500.00",
  "moneda": "MXN",
  "tipo": "deposito",
  "billetera_id": "wallet_x1y2z3",
  "idempotency_key": "dep_unique_abc123"
}
EOF

# Variante inválida: monto numérico (no string)
echo '{"monto": 1500, "moneda": "MXN", "tipo": "deposito", "billetera_id": "w1", "idempotency_key": "k1"}' > invalido.json
```

**Salidas esperadas:**

```
$ bash validar-contrato.sh transaccion-request.json
CONTRATO VÁLIDO

$ bash validar-contrato.sh invalido.json
CONTRATO INVÁLIDO:
  - monto debe ser string, no number

$ echo '{"monto":"100","moneda":"MXN","tipo":"cargo","idempotency_key":"k"}' | bash validar-contrato.sh
CONTRATO INVÁLIDO:
  - tipo 'cargo' no es válido (usar: deposito, retiro, transferencia)
```
