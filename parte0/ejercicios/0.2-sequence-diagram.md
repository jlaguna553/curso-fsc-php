# Ejercicio 0.2: Diagrama de Secuencia de un Depósito

## Objetivo

Visualizar el flujo completo de una transacción de depósito entre
microservicios, identificando las responsabilidades de cada componente.

## Contexto

En PrestaFlow, un depósito toca 4 componentes: el cliente, el gateway, el
servicio de billeteras y el bus de eventos. Antes de escribir código, debes
entender este flujo y saber qué valida y procesa cada componente.

> **¿No conoces Mermaid?** Se cubre en la lección 0.2, sección
> *"Diagramas de Secuencia con Mermaid"*: `sequenceDiagram`, `participant`,
> flechas `->>`/`-->>` y bloques `alt`. Léela antes de empezar.

## Instrucciones

Modela el depósito con un **diagrama de secuencia** (formato Mermaid). Tu
diagrama debe tener 6 participantes:

1. **Cliente (App/Web)**
2. **API Gateway (Nginx)**
3. **Wallet Service (PHP)**
4. **PostgreSQL**
5. **RabbitMQ**
6. **Notification Service**

El flujo a modelar, en orden, es:

1. El cliente envía la petición de depósito (POST con monto, moneda y tipo).
2. Se valida la identidad del cliente antes de procesar.
3. Se validan los datos recibidos contra el contrato JSON.
4. Se consulta el balance de la billetera y se verifica que alcance para el
   depósito.
5. La operación se registra de forma atómica en la base de datos
   (BEGIN/COMMIT: INSERT de la transacción y UPDATE del balance).
6. El cliente recibe una respuesta de éxito con el ID creado y el balance
   nuevo.
7. Se publica un evento para que otros servicios reaccionen.
8. El Notification Service genera y envía un email de confirmación.

Usa mensajes `->>` (síncronos) y `-->>` (respuestas), y bloques `alt` para
las ramas de error.

### Opción A: Mermaid Live Editor

1. Ve a https://mermaid.live
2. Escribe tu diagrama con `sequenceDiagram`.
3. Exporta como PNG o SVG.

### Opción B: Diagrama en Papel

1. Dibuja 6 columnas: Cliente, API Gateway, Wallet Service, PostgreSQL,
   RabbitMQ, Notification Service.
2. Traza flechas horizontales con los mensajes.
3. Usa notas al pie para indicar los códigos HTTP.

<summary>🔍 Ver solución de referencia</summary>

```mermaid
sequenceDiagram
    participant C as "Cliente (App/Web)"
    participant GW as "API Gateway (Nginx)"
    participant WS as "Wallet Service (PHP)"
    participant DB as PostgreSQL
    participant MQ as RabbitMQ
    participant NS as Notification Service

    C->>GW: POST /api/v1/transacciones<br/>{"monto":"1500.00","moneda":"MXN","tipo":"deposito"}
    GW->>GW: Validar token JWT en Authorization header
    alt Token inválido
        GW-->>C: 401 Unauthorized {"error":"Token inválido"}
    end
    GW->>WS: Forward: headers + body
    WS->>WS: Validar contrato JSON (campos requeridos)
    alt Contrato inválido
        WS-->>GW: 422 Unprocessable {"error":"Campo 'billetera_id' requerido"}
        GW-->>C: 422 Unprocessable
    end
    WS->>DB: SELECT balance_actual FROM billeteras WHERE id = 'wallet_x1y2z3'
    DB-->>WS: balance: 5000.00
    WS->>WS: Verificar: 5000.00 >= 1500.00 ✓
    WS->>DB: BEGIN TRANSACTION
    WS->>DB: INSERT INTO transacciones (billetera_id, monto, moneda, tipo, estado, idempotency_key)
    DB-->>WS: OK (1 row inserted)
    WS->>DB: UPDATE billeteras SET balance = 6500.00 WHERE id = 'wallet_x1y2z3'
    DB-->>WS: OK (1 row updated)
    WS->>DB: COMMIT
    DB-->>WS: OK
    WS->>MQ: Publicar evento "transaccion.completada" en exchange prestflow.events
    WS-->>GW: 201 Created {"id":"txn_abc","balance_nuevo":"6500.00"}
    GW-->>C: 201 Created
    MQ->>NS: Consumir evento "transaccion.completada"
    NS->>NS: Generar email de confirmación
    NS->>NS: Enviar email a usuario
    NS-->>MQ: ACK (mensaje procesado)
```
